# Running in PyCharm

Five minutes, no plugins.

## 1. Open the project

**File → Open** → select the `InvestigateCelra` folder (the one containing
`run.py`). Open the folder itself, not a parent directory.

## 2. Create the interpreter

**Settings → Project → Python Interpreter → Add Interpreter → Add Local →
Virtualenv**, base interpreter Python 3.11 or newer, location
`InvestigateCelra/.venv`. Click OK and let PyCharm create it.

Then in the built-in Terminal (Alt+F12):

```bash
pip install -r requirements-dev.txt
```

PyCharm may also offer this as a banner notification when it notices
`requirements.txt` — either route is fine.

## 3. Mark `backend` as a sources root

Right-click the **`backend`** folder → **Mark Directory as → Sources Root**.

This is only for the IDE. Without it, PyCharm underlines
`from investigatecelra...` in red and autocomplete does not work, even though
the code runs fine, because `run.py` adds the path at runtime. With it, both
the editor and the runtime agree.

## 4. Configure the environment

```bash
cp .env.example .env
```

Open `.env` and set `HTTP_USER_AGENT` to a real contact address. NCBI and
ClinicalTrials.gov ask for one and rate-limit anonymous callers harder.

`run.py` reads `.env` itself, so nothing else is needed. Real environment
variables always take precedence over the file.

## 5. Verify the sources before you run

In the Terminal:

```bash
make verify
```

or, on Windows where `make` may not exist:

```bash
python scripts/verify_sources.py
```

This makes a real request to every source and prints the record count, newest
headline and publisher URL for each. It is the fastest way to confirm the
pipeline works end to end. There is no bundled corpus, so if every source
fails the app will show an empty edition rather than invent one.

## 6. Run

Open `run.py` and click the green **Run** arrow, or right-click → **Run
'run.py'**. PyCharm creates the run configuration automatically.

The console prints the uvicorn banner and a clickable
<http://127.0.0.1:8000>. The first load shows "Building the first edition"
while the initial fetch runs in the background — 20 to 60 seconds depending on
how the public APIs are responding — then the page loads itself.

Reload is on for both `backend/` and `frontend/`, so editing a Python module,
a JS file or the CSS and saving is enough; refresh the browser.

## 7. Run the tests

Right-click the **`tests`** folder → **Run 'pytest in tests'**. 52 tests, all
green.

If PyCharm reports import errors in the test files, step 3 was skipped —
`tests/conftest.py` inserts `backend/` on `sys.path` at runtime, but PyCharm's
inspector needs the sources root to see it too.

## Debugging

Breakpoints work normally, with one caveat: uvicorn's reloader runs the app in
a child process, so breakpoints in request handlers may be skipped. If that
happens, edit the run configuration and add `RELOAD=0`, or temporarily set
`reload=False` in `run.py`.

Good places to put a first breakpoint:

| Question | File |
|---|---|
| Why did this story get this label? | `engine/classify.py`, in `classify()` |
| Why did it rank here? | `engine/score.py`, in `compute()` |
| Why was this entity recognised? | `engine/entities.py`, in `Gazetteer.extract()` |
| What did the feed actually return? | `ingest/rss.py`, in `parse_feed()` |

## Common problems

**`ModuleNotFoundError: investigatecelra`** — you ran a file inside
`backend/investigatecelra/` directly instead of `run.py`. Always start from
`run.py`.

**Port 8000 in use** — set `PORT=8001` in `.env`.

**Page stays on "Building the first edition"** — run `make verify`. If every
source fails, outbound HTTPS is blocked, likely by a corporate proxy or VPN.
The desk will not fall back to placeholder content.

**Interactive API docs** — <http://127.0.0.1:8000/docs>, generated by FastAPI
from the type hints. Useful for demonstrating the API without the UI.
